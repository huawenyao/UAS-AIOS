# UAS-AIOS AI 产品宪章

> **地位**：道/德层的产品决策法。约束「做什么、不做什么、如何体验、如何上 Agent」。  
> **不是**：理论复述、功能清单、西方 UX 名录。  
> **引用**：`宪章·道-n` / `宪章·德-*` / `宪章·势-n` / `宪章·INV-*`。  
> **权威理论**：[`THEORY_SYSTEM.md`](./THEORY_SYSTEM.md)。本宪章只编译为可执行约束。  
> **版本**：v1.1 · 2026-08-18 · 演化见 §九。

---

## 如何使用本宪章（先读这一段）

评审功能、设计页面、定义 Agent 行为时，按同一条链路走，不要跳层：

1. **道**：这件事是否走完「输入→模拟→生成→交互→进化→输出→收益」？若只增加对话或自动化率，否决。  
2. **德**：对用户是「让主体变强」还是「替主体做完」？对组织是否进入可审计经营闭环？是否触碰红线（G6、静默越权、无证据决策）？  
3. **势**：先写出当前张力（认知/执行/知识摩擦、人机环位、理想/现实、效率/治理、双轨权限），再决定降低哪一侧摩擦、**不得假装张力不存在**。  
4. **术**：把方案映射到 `intent_activation → evaluation` 与价值闭环 7 步；每一步必须有主客体、证据、反馈通道。  
5. **器**：对照 SelfPaw / ΠPaw / ASUI 体验契约与 §八不变式；过不了 `宪章·INV-*` 的不进入生产。

争议时：**德压过术，势先于术，G 层否决权高于增长指标。** 本宪章与工程实现冲突时，改实现或走 §九 反身修订，禁止口头豁免。

## 2. 元原则（道）

不可谈判。违反任一条，功能不得称为 UAS 产品。

### 道-1 认知实践是价值路线

- **含义**：产品存在的理由是让主体在真实工作中完成「实践→表征→反馈→反思→再实践」，并产生可归因收益。  
- **为什么**：项目核心命题；价值闭环 7 步是其工程形态。聊天、演示、自动化率都不是终点。  
- **产品含义**：每个功能必须声明它落在 7 步的哪几步，以及收益如何回流。  
- **反例**：加一个「AI 对话框」却不进入工作流、不写审计、不更新世界模型。

### 道-2 世界模型是一级公民

- **含义**：产品必须显式维护空间、时间、主体、客体、感知—行动—反馈；Agent 在其上行动，而不是在 prompt 里即兴。  
- **为什么**：AGI = WM ⊕ Agent；WM 是法则编译器（降维求解），不是预测器。  
- **产品含义**：界面与 Agent 输出必须能指出：谁在做、对谁做、作用对象、时间约束、反馈从哪来。缺一则任务未建模。  
- **反例**：黑箱分数排序、无主客体的「智能摘要」、把 RAG 片段当作世界。

### 道-3 智能即降维

- **含义**：智能的本质是降低复杂度，不是堆功能、堆 Agent、堆面板。  
- **为什么**：世界模型机制是「高维混沌 → 低维有序 → 映射回现实」；理念简单有序，现实复杂混沌。  
- **产品含义**：默认只暴露当前主客体决策所需的信息；其余渐进展开。新控件必须证明它减少了认知摩擦（U）。  
- **反例**：把全部证据、全部 Agent 日志、全部系统字段一次性铺在首屏。

### 道-4 知识即配置，构建即运行

- **含义**：行为变化优先写进显式知识（CLAUDE.md / skills / workflow / policy / Domain Pack），下次执行即生效；代码只承载确定性执行。  
- **为什么**：ASUI 三大支柱；模型负责理解与生成，平台负责执行与保障。  
- **产品含义**：可配置的规则不得藏进模型权重或一次性 prompt；用户（含业务专家）应能看见并修订「系统为何这样」。  
- **反例**：改打分标准必须改代码发版；Agent 直连 CRM REST。

### 道-5 双轨不混权

- **含义**：User AGI（SelfPaw）与 Business AGI（ΠPaw）共享 Kernel，不共享默认数据 scope、对外通道与经营承诺权。经营类意图必须带证据升级，禁止静默越权。  
- **为什么**：ADR-EDH-001；企业要的是组织能力可执行化，不是个人 Agent 进生产。  
- **产品含义**：员工视图 ≠ 指挥席；对外通道默认仅 ΠPaw；C 端能力不得原样当作 B 端权限模型。  
- **反例**：SelfPaw 直接给客户发报价；ΠPaw 读取未授权的个人记忆。

### 道-6 理念必须对冲现实

- **含义**：未与现实状态、事件、主体评价对冲的理念，不得当作已交付。  
- **为什么**：三阶段演进的终点是理念—现实一体化；triadic 蜂群的方法是理念 vs 现实对冲。  
- **产品含义**：方案、画像、策略必须同时展示「应当如何」与「当前事实」，并标出差距与下一步验证。  
- **反例**：只生成理想 JD / 理想话术 / 理想 KPI，没有对照真实候选人、真实工单、真实转化。

## 3. 价值约束（德）

德是主体价值函数。产品必须同时对**使用主体、组织主体、被作用客体（含社会）**交代价值取向。无德的势是有害的。

### 3.1 对用户（使用主体）

| ID | 约束 | 产品含义 | 反例 |
|----|------|----------|------|
| **德-用户-1 让主体变强** | 产品使人更能完成其目标工作，而不是使人退出判断 | 证据、追问、校准、可撤销；能力增益可感知 | 全自动淘汰、替代面试官、用户只会点「同意」 |
| **德-用户-2 先澄清意图** | 模糊输入不得直接执行高影响动作 | 追问目标、成功标准、约束、失败反例（招聘 Hiring Mission 已示范） | 一句话生成 JD 并对外发布 |
| **德-用户-3 价值必须可感知** | 痛点被解决不等于用户感觉到被解决 | 入口可用、结果可见、节省/风险/下一步一眼能读 | 能力只在脚本与 JSON 里，业务用户用不上 |
| **德-用户-4 诚实** | 不确定、缺失、幻觉、越权风险必须显式 | 「不知道」优于伪装确定；证据缺口单独呈现 | 黑箱分数、静默补全虚构经历 |

### 3.2 对组织

| ID | 约束 | 产品含义 | 反例 |
|----|------|----------|------|
| **德-组织-1 经营闭环先于自动化片段** | 单点 Copilot 不是产品 | 获转服续 / 招聘闭环 / 工单闭环必须能走到输出与收益 | 只做邮件润色，不进 CRM 与 SLA |
| **德-组织-2 岗位先于人格** | 先职责、授权、KPI、红线，再类人交互 | Agent 编制绑定岗位 Domain，而不是绑定人设 | 「有个性的数字员工」无权限矩阵 |
| **德-组织-3 模型提议，平台执行** | LLM 不得成为生产动作的执行者 | 规划可生成；写库、发信、报价、付款走 `cs.*` + 门禁 | Agent 持生产库凭证直连 |
| **德-组织-4 收益可归因** | 无北极星与回流的演化是空转 | 每条产品线声明北极星及输入指标（招聘已用 quality-adjusted hiring success） | 只报 token 消耗或对话轮次 |

### 3.3 对社会与被作用客体

被作用客体（候选人、客户、伙伴、公众）是世界模型的主体维度，不是「通知附属」。

- **德-社会-1**：高影响拒绝/承诺必须可解释、可申诉或至少经人工确认后体面传达。  
- **德-社会-2**：禁止歧视性自动化；公平合规 Agent / G6 为强制存在，不是可选插件。  
- **德-社会-3**：数据主权：个人轨本地/授权；企业轨租户隔离。不可导出、不可审计的记忆不得进入生产。

### 3.4 红线（不可豁免）

触碰即拦截，记安全审计，不得用「实验」「演示」「用户同意了条款」绕过。

1. **G6**：违法、越权、歧视、泄密。  
2. **无证据不得推进审批与对外承诺**（不足则 `EVIDENCE_REQUIRED`）。  
3. **Agent 禁止裸调业务系统**（ADR-EDH-002）。  
4. **高影响决策必须人确认**（录用/拒绝、报价/合同、对外承诺、自动淘汰）。  
5. **禁止静默权限升级**（SelfPaw → ΠPaw 必须 Intent + Evidence）。  
6. **禁止不可回滚的生产写入**作为默认路径。

编译说明（不作为并列框架）：Rams「有用/诚实/克制」、Norman「价值可感知」、Cooper「目标导向」、Kathy Sierra「让用户变强」已分别落入德-用户与德-组织，不再单独引用为决策依据。

## 4. 张力场（势）

势是决策前必须写明的差异结构。没有势，术是盲目的。

产品决策用下面六组张力**显式选边或显式折中**，禁止用「我们都要」代替选择。

### 势-1 ASUI 三元摩擦（宪法级）

| 摩擦 | 定义 | 产品要降低它时 | 过度降低的代价 |
|------|------|----------------|----------------|
| **认知摩擦 U** | 用户把意图变成可执行指令的成本 | 情景化上下文、意图澄清、渐进披露 | 过度猜测 → 错误执行 |
| **执行摩擦 A** | 指令变成专业结果的自主程度 | `cs.*`、工作流、On/Above loop | 过度自主 → 越权与不可逆 |
| **知识摩擦 S** | AI 与领域语义的鸿沟 | 显式知识、Domain Pack、证据接地 | 只检索不治理 → 幻觉装作知识 |

UAS 产品的目标不是三轴同时拉满口号，而是在 **G 约束 C(t)** 下选择帕累托点。自主性轴必须标明环位：

| 环位 | 含义 | 默认适用 |
|------|------|----------|
| **In the loop** | 人逐步驱动 | 意图澄清、校准、G3+ |
| **On the loop** | 人监督可打断 | G2、个人任务、草稿 |
| **Above the loop** | 人设目标与红线，事后审计 | 仅授权内、可回滚、有 KPI 回流 |

环位升级必须经过治理，不得因「用户嫌点确认」而偷偷上移。

### 势-2 人机分工

人做决策、定目标、承责；AI 做增强、推演、执行确定性动作。  
**推动 / 阻碍 / 连接**三视角必须出现在方案评审：谁被赋能、谁被阻滞、接口在哪。招聘 OS 的「人做决策，AI 做增强」是本条的领域实例。

### 势-3 理想 / 现实

每一份生成物同时带理念层（ought）与现实层（is）及差距。triadic 模板是方法，不是装饰。

### 势-4 效率 / 治理

治理是设计约束，不是上线后贴的合规贴纸。G0–G6 决定交互密度：G0 可以快，G4 必须慢。  
**约束即设计**：审批、证据、回滚应成为主路径上的可见结构，而不是弹窗打断。

### 势-5 双轨势能

SelfPaw 积累个人意图与证据；ΠPaw 消耗组织授权与经营通道。势能只能经 Intent Hub 定向释放。混用入口就是混权（违反道-5）。

### 势-6 能力 / 信任

能力增长若不同步于可解释、可撤销、可审计，信任下降，采用率下降。Cognitive Agent 文档中的「渐进自主」是本条的术：白盒与门禁先于自主级别。

决策用法：立项一页纸必须有「张力表」——当前主摩擦、选择的环位、被牺牲的一侧、监控指标。没有张力表的方案视为未完成势分析。

## 5. 设计术（术）

术只在势清楚之后使用。下列步骤把认知实践 7 步与 ASUI 工作流叠合；外部 UX 方法已编译进步骤名，不再并列。

### 5.1 标准设计工作流

```
意图澄清 (I)     → 价值闭环「输入」     → intent_activation / understanding
世界建模 (K)     → 「模拟」的对象         → knowledge_binding
方案生成 (A)     → 「生成」             → planning / agent_planning
触点与执行 (R/S) → 「输出」前置          → execution / system_mapping
人机协同 (G)     → 「交互」             → governance_check / human_review
监测与可见 (UI)  → 摩擦是否下降          → monitoring / render_report
评价与回流 (E)   → 「进化」「收益」       → evaluation / ChangeSet
```

Studio / Kernel 的八阶段（`intent_activation` … `render_report`）是本表的工程展开，不得另造一套产品流程。

### 5.2 可执行方法（按步）

**1. 意图澄清（目标导向，而非功能清单）**  
问：主体要完成的「工作」是什么（客体上的状态变化），成功标准、周期、约束、失败反例。禁止把用户原话直接当任务名。招聘 Hiring Mission、SelfPaw Intent Hub 是范型。

**2. 主客体编目（JTBD 的世界模型形式）**  
列出决策者、执行者、评审者、受益方、受损方；列出被操作客体及其生命周期。交付物必须映射到「谁接收、谁使用、谁评价」。

**3. 法则编译，而非界面堆砌**  
先写本源约束（宏观法则 → 岗位微观规则），再投影为当前情景的默认路径。UI 只是投影结果。

**4. 多方案 + 对冲**  
至少生成可比较方案；蜂群/红蓝对抗用于高不确定性决策（selfpaw 五智能体、第一次否定→第二次否定）。单答案的「AI 建议」只允许出现在 G0–G1。

**5. 渐进披露**  
首屏：结论、关键证据、风险、下一步。展开：证据链、冲突、假设。再展开：原始材料与 Agent 轨迹。这是降认知摩擦的术，不是把信息藏起来。

**6. 先解释，再建议，再动作**  
建议必须挂证据；动作必须挂门禁与可撤销声明。无解释的建议视为幻觉风险。

**7. 把体验当进化信号**  
点击、驳回、改写、审批超时、NPS、短名单接受率，一律视为反馈，经归因后进入 ChangeSet，不得只当「运营数据」沉在看板。Lean UX / Dual-Track 在本体系中 = 推动—反馈—反身，而不是独立研发流程。

**8. 北极星服务于收益步**  
北极星必须是质量调整后的业务结果（如 quality-adjusted hiring success、一次解决率、合规承诺差错），禁止用模型分数或自动化占比替代。输入指标可多，北极星唯一。

### 5.3 Agent 行为设计术

- 只调用 `cs.*`；规划与执行分离。  
- 输出结构：意图理解、所用知识、证据、不确定点、建议动作、所需门禁、回滚方式。  
- 幻觉治理：陈述必须接地到客体记录或显式知识；否则标为「未接地假设」。  
- 可撤销：G2 以上动作预宣布回滚窗口；不可逆动作升环位。

## 6. 器与触点（器）

器是用户看见的产品。没有契约的触点，宪章停留在口号。

### 6.1 ASUI 触点契约（Kernel / Studio / subapp）

面向：构建者、业务专家、Agent 编排。

| 必须 | 禁止 |
|------|------|
| 知识文件可被非技术人员读懂系统行为（ASUI 特征①） | 逻辑只存在于对话历史 |
| 改知识后无需重启即可改变行为（特征②⑥） | 新意图必须发版才能试 |
| 步骤、输入、知识依据可审计（特征⑤） | 纯文本「已完成」无结构化落盘 |
| UI 呈现结构化结果与下一步，而非只聊天（特征③④） | 用 Chat 冒充 Workspace |
| 模板生成的最小闭环含知识+脚本+审计+演化 | 只有 prompt 的「应用」 |

`asui init` 产出的是可运行骨架；产品体验要在此骨架上补主客体触点，否则重复招聘 OS 的教训：批处理很强，HR 感知为零。

### 6.2 SelfPaw 体验契约（User AGI / L1）

面向：个人或组织内员工。参考实现：`aipos/copaw-src`；本仓库只做企业桥接。

1. **一个入口，意图优先**：用户表达目标，系统加载个人/岗位世界模型，而不是让用户选择 20 个技能。  
2. **第二大脑，不是第二领导**：个人任务可 On loop；经营动作必须升级 ΠPaw。  
3. **记忆与偏好可见、可删、可导出**（用户主权）。  
4. **蜂群对冲默认折叠**：多立场推演的结论先出，过程可展开；禁止五份报告同时砸向用户（道-3）。  
5. **证据盒随意图走**：升级组织任务时，证据是一等公民，不是附件。

### 6.3 ΠPaw 体验契约（Business AGI / L2–L3）

面向：职能专员、管理者、经营岗位、对外客户（经 Outward Gateway）。  
**产品形态**：World Model Studio（认知实践世界模型）。ΠPaw 是编排身份，不是数字人 App。权威原型：`examples/world-model-studio/` · [`WORLD_MODEL_PRODUCT.md`](./WORLD_MODEL_PRODUCT.md)。

1. **一级公民是世界模型，不是人设**：首屏暴露当前决策的五维低维结构（谁、对谁、何时、何法则、何反馈），禁止 Agent 列表/聊天入口冒充工作台。  
2. **价值闭环 7 步是主路径**：输入→模拟→生成→交互→进化→输出→收益每步读写世界模型；对话历史不是状态。  
3. **理念 vs 现实必须对冲**：ought/is 同时在场；未接地分数不得流入建议（INV-05）。  
4. **G0–G6 与环位是主路径结构**：用户应知道「这是草稿 / 这要经理批 / 这被禁止」；高影响默认 In the loop。  
5. **模型提议，平台执行**：可预览 `cs.*`；禁止 runtime 把 LLM 当生产执行器。  
6. **被作用客体是主体维度**：候选人/客户进度、拒绝反馈、SLA 进入 `dimensions.subject`，不是通知附件。  
7. **体验即进化**：驳回、改写、确认超时写入 ChangeSet，回写法则 Pack。

### 6.4 协议与运行时如何「被体验到」

| 器 | 用户可感知的形态 |
|----|------------------|
| **I / UIP** | 意图被复述、边界被确认、成功标准可编辑 |
| **K** | 规则、权重、Domain Pack 可打开 |
| **R** | 任务状态、隔离、失败可重放 |
| **A** | 哪个岗位 Agent 做了什么，可打断 |
| **S / cs.\*** | 「将写入哪条业务对象」可预览 |
| **G** | 门禁、审批人、拦截理由 |
| **E** | 反馈如何改变下次行为（ChangeSet 摘要） |
| **Π** | 通道、身份、审计号 |

若协议只存在于仓库而从不出现在 UI，视为器层违约。

## 9. 演化条款

本宪章是知识配置，适用「修改即生效」，但**原则层变更必须走反身**，禁止静默改道。

```
推动：产品争议、事故、INV 失败、北极星持续偏离
  → 反馈：主客体评价、审计、收益归因、场景走查
  → 反身：判断是实现违约，还是原则过时
  → 推动：改实现 / 或修订宪章条款并升版本
```

| 可热更新 | 必须反身修订（升 vN.x） |
|----------|-------------------------|
| 检核清单措辞、领域范例、对照表路径 | 道条增删、红线、INV 语义、双轨边界 |
| 术的步骤说明、渐进披露细则 | 环位默认值、G 级与人确认范围 |

修订规则：

1. 提案须指出张力（势）与被牺牲项，附反例。  
2. 与 `THEORY_SYSTEM.md` 冲突时，先改宪章以服从理论，或同步修订理论并说明相变。  
3. 与已 Accepted ADR 冲突时，先改 ADR 或撤回产品行为。  
4. 修订后更新本节版本、CLAUDE.md 索引（若条目名变化）及对应 harness 断言。  
5. 废止条款保留一行「废止原因」，禁止删史。

**v1.1（2026-08-18）**：§6.3 器层从「经营数字人工作台」反身改为 World Model Studio。废止原因：实现把岗位人格与 Task Panel 当作产品，世界模型不可见、不参与 7 步。道条未改。

## 1. 三条业务命题

| # | 命题 | 业务含义 |
|---|------|---------|
| **P1** | 目标 ≡ 数据 | 销售目标、客户指标、团队 KPI 是同一棵树的三种说法，不是三套系统 |
| **P2** | 端 · 云 · 底 | 端是作战台（看见并决定），云是 AI 中台（编译并执行），底是数据和系统（提供事实） |
| **P3** | 看见并办成 | 不只是看报表，而是知道该干什么、AI 帮你干、结果自动回 |

## 2. 核心逻辑：目标 ≡ 数据（业务语言版）

### 2.1 为什么必须是同一套

传统方式的问题：

| 场景 | 传统方式 | 结果 |
|------|---------|------|
| 销售总监定目标 | 定 $5M 目标，分解到团队 | 目标停在 PPT，不知道每天该干什么 |
| 客户经理看数据 | 打开 CRM，翻客户记录 | 数据躺在系统里，不知道该怎么用 |
| 管理者发现问题 | 等周报，看漏斗 | 问题发现时已经晚了 |

**WorkStudio 的方式**：

```
目标 $5M
  ↓ 分解到团队
团队目标 $5M
  ↓ 分解到个人
个人目标 $500K
  ↓ 分解到客户
客户A 目标 $150K / 月
  ↓ 实时监控
客户A 实际 $120K / 月（缺口 $30K）
  ↓ 分析原因
拜访停留 28 天，决策链未覆盖
  ↓ 推荐动作
安排 C-level 拜访
  ↓ 一键派活
任务给 BD·张三，截止 08-23
  ↓ 执行追踪
任务完成，客户状态更新
```

### 2.2 责任节点（业务语言版）

每一个可管理的经营位置，必须同时具备：

| 要素 | 业务语言 | 例 |
|------|---------|---|
| **目标** | 这个月要签多少单 | 客户A 目标 $150K |
| **负责人** | 谁负责这个客户 | CM·cowen.hua + BD·张三 |
| **客户** | 对哪些客户负责 | 客户A · Shopline |
| **指标** | 用什么衡量进度 | 消耗、转化率、周期 |
| **流程** | 卡在哪段流程 | 拜访阶段，停留 28 天 |

## 3. 三层架构（业务语言版）

```
┌─────────────────────────────────────────────────────────┐
│ 端 · 作战台（我的首页）                                  │
│  今日必办 · 客户作战室 · 团队指挥舱                      │
│  看见并决定：今天该干什么、哪个客户要丢、该派谁去        │
├─────────────────────────────────────────────────────────┤
│ 云 · AI 中台（帮你干活）                                 │
│  研究：为什么卡？怎么破局？                              │
│  构建：把打法固化成流程                                  │
│  运行：带权执行，写 CRM，回写状态                        │
├─────────────────────────────────────────────────────────┤
│ 底 · 数据和系统（提供事实）                              │
│  CRM · 数仓 · 审批系统 · 邮件 · 日历                     │
│  提供客户数据、执行动作、记录结果                        │
└─────────────────────────────────────────────────────────┘
```

### 3.1 端：作战台（我的首页）

| 模块 | 你看到什么 | 你能干什么 |
|------|-----------|-----------|
| **今日必办** | 3 个客户要跟进，2 个审批要催 | 确认、调整、转派 |
| **客户作战室** | 客户 360、卡点分析、下一步动作 | 确认执行、调整策略 |
| **团队指挥舱** | 漏斗分析、人员状态、资源调配 | 调配客户、支援请求 |

### 3.2 云：AI 中台（帮你干活）

| 模式 | 什么时候用 | AI 干什么 |
|------|-----------|----------|
| **研究** | 客户为什么卡？ | 分析数据、找原因、给方案 |
| **构建** | 打法要固化 | 把方案编成可复用流程 |
| **运行** | 任务要执行 | 带权执行、写 CRM、回写状态 |

### 3.3 底：数据和系统（提供事实）

| 系统 | 提供什么 |
|------|---------|
| CRM | 客户数据、互动记录、阶段状态 |
| 数仓 | 消耗、转化率、业绩指标 |
| 审批系统 | 合同审批、报价审批、折扣审批 |
| 邮件 / 日历 | 拜访安排、会议纪要、跟进提醒 |

## 4. 双轨合流（业务语言版）

### 4.1 传统 Dashboard 停在哪

```
CRM / 数仓 → 报表 → 人看 → 人想 → 人切到另一个系统去办
                              ↑
                              └── 闭环在这里断掉
```

### 4.2 WorkStudio 的方式

```
        看见（指标轨）                    办成（执行轨）
        数据 → 洞察 → 决策                决策 → 任务 → 执行 → 结果
                 ↘                      ↙
                   同一客户 · 同一目标
                   （合流点）
```

| 轨 | 你做什么 | 系统做什么 |
|----|---------|-----------|
| **看见** | 打开作战台，看今日必办 | 告诉你哪个客户要丢、为什么 |
| **办成** | 确认动作，派任务 | AI 执行，写 CRM，回写状态 |
| **合流** | 任务完成，客户状态更新 | 数据自动回写，下次打开看到最新状态 |

## 5. 核心场景（业务语言版）

### 场景 1：早上打开，知道今天干什么

```
08:30 打开 WorkStudio
  ↓
「今日必办」：
  🔴 客户A：28 天没拜访，流失风险高
     → [一键派任务] 给 BD·张三
  🟡 客户B：合同审批卡 9 天
     → [一键催办] 给法务
  ↓
08:35 确认派任务，AI 生成拜访议程
08:40 开始一天工作
```

### 场景 2：客户作战室，一眼看清

```
点进「客户A · Shopline」
  ↓
客户 360：基本信息、历史互动、当前阶段、健康度
卡点分析：为什么卡在这里？数据说话
下一步动作：AI 推荐，你确认或调整
执行追踪：任务进度、审批状态、客户反馈
```

### 场景 3：团队指挥舱，实时救火

```
销售总监打开「团队指挥舱」
  ↓
业绩总览：目标 vs 实际，缺口在哪
漏斗分析：哪个阶段转化率低，为什么
人员状态：谁超负荷，谁闲着，谁需要帮助
资源调配：一键调配客户、支援请求
```

## 6. 与传统方式的区别

| 维度 | 传统 CRM | 传统 BI | WorkStudio |
|------|---------|---------|-----------|
| 打开看到什么 | 客户列表 | 图表 | 今天该干什么 |
| 知道客户卡了 | 自己翻记录 | 看报表发现 | 主动预警 |
| 知道为什么卡 | 自己分析 | 自己猜 | AI 告诉你 |
| 知道该干嘛 | 自己想 | 自己想 | AI 推荐，你确认 |
| 执行追踪 | 手动更新 | 不追踪 | 自动闭环 |

## 8. 体验不变式（业务语言版）

1. **打开就知道干什么**：首页就是今日必办  
2. **客户状态一眼清**：红绿灯 + 一句话说明  
3. **下一步动作 AI 给**：确认或调整就行  
4. **执行结果自动回**：不需要手动更新  
5. **团队协作不费劲**：任务派发、状态同步、一键完成

# AWM 产品 Demo 设计：补货世界闭环

> 切合产品定位：**人与 Agent 共用的可操作世界**。  
> 切合设计原则：World-first、对象必具名、Now ≠ Maybe、类型错误、审批托盘、做完必回看。  
> 可运行：`python3 scripts/awm_demo_loop.py` 后打开 `website/awm-demo/index.html`。

---

## 1. Demo 要证明什么（不是功能巡礼）

8 分钟只证明一件事：**Agent 动手之前，人和审批者看见同一世界；动手之后，世界会回嘴。**

| 竞品默认 Demo | 本 Demo 必须相反 |
|---------------|------------------|
| 打开对话框，「帮我补货」 | 打开世界画布，先看见 `sku:A` |
| 模型直接生成采购建议 | 先匹配 SKU=Gate，再演，再批 |
| 成功 = 一段流畅回答 | 成功 = 无审批 blocked，有审批才 committed，然后 OBSERVE |

非目标：不演示大模型对话能力、不演示全企业本体、不演示自动驾驶世界模型。

---

## 2. 闭环（七拍，不可跳拍）

```
匹配 Match → 看见 Lens → 意图 Intent → 计划 Plan
    → 推演 Stage → 门控 Gate → 回看 Observe →（反身，下一螺旋）
```

对应 SIO-MMOS/DIKW：Match 定 SKU；Lens 补 S；Intent 固化 I；Plan/Stage/Gate 走 O；Observe 把 W 收回 D。

| 拍 | 角色 | 屏幕高潮 | 一句话亮点 | 主按钮 |
|----|------|----------|------------|--------|
| 1 匹配 | 架构师旁白 | 五问结果：`gate` + 虚影对象 | 先匹配结构，不先聊天 | 进入世界 |
| 2 看见 | 操作员 | 画布 + 情境条缺口：ERP 40 vs Excel 52 | 对象必具名，分裂被点亮 | 解释这个对象 |
| 3 意图 | 操作员 | 约束芯片：预算 50 万 / 风险 <5% | 改芯片即重编译 | 生成计划 |
| 4 计划 | 操作员 | 三张动作卡；点「删库」弹出类型错误 | 失败是类型错误不是道歉 | 演一遍 |
| 5 推演 | 操作员 | Now 40 / Maybe 130，中间「未写入」 | 看见未来且知道它还不是真 | 提交审批 |
| 6 门控 | 审批人 | 托盘：金额、对象、不可逆=否 | 审批不是 IM | 批准写回 |
| 7 回看 | 全员 | 预测风险 0 vs 观测 3%，DIKW 全绿 | 世界会说话，闭环可进入下一螺旋 | 结束本轮 |

## 3. 演示剧本（对白按拍）

**开场（20s）**  
「这不是聊天机器人。首页没有输入框。这是仓 W1 的可操作世界。」

**拍 1**  
问五件：谁签字、改哪个 ID、哪条线不能破、能执行哪三件事、多久能看见。匹配器给出 Gate，不是「智能助手」。

**拍 2**  
指 `sku:A`、`wh:W1`。指出情境条琥珀色缺口：Excel 与 ERP 对不上——Lens 的价值就是把分裂摊开。

**拍 3**  
读出目标：「两周内缺货风险 < 5%，预算 ≤ 50 万」。强调芯片，不强调 prompt。

**拍 4**  
走查询 → 采购单（琥珀，需审批）→ 通知。故意点未注册动作，屏幕出现 `unregistered action: erp.drop_table`。

**拍 5**  
分屏：左 18% 风险，右 0%；缎带写「仿真未写生产」。`writes_facts=false` 是卖点。

**拍 6**  
切到审批人壳：不进画布。托盘里只有对象、数量 80、金额 6400、需人批。先展示未批 = blocked，再批准 = committed。

**拍 7**  
观测 on_hand 因出库略低于预测，风险 3% 仍达标。校准通过。DIKW 看板作为是否保持 Gate 的证据。

**收束（20s）**  
「聊天在右下角，只能问当前切片。世界是舞台，对话是灯光。」

---

## 4. 界面必须出现的元件

情境条、世界画布、意图芯片、动作时间线、Now/Maybe 分屏、审批托盘、Explain 结构句、类型错误 Toast、角色切换（操作员/审批人）、被锁定的「问这个世界」。缺任一元件则 Demo 不合格。

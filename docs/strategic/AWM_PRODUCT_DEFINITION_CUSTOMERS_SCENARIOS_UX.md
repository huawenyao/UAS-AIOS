# Agent 世界模型产品定义：客户、场景、交付、竞争与体验

> **产品内部名**：Agent World Model（AWM）  
> **对客一句话**：人与 Agent 共用的可操作世界——看见同一对象、遵守同一约束、在门控下改同一事实。  
> **方法**：SIO-MMOS/DIKW。知识建模用 Subject–Interaction–Object；运行时用 Situation–Intent–Operation。  
> **在交付体系中的位置**：UAS Kernel 的一等能力，经 UAS Studio 构建，经 ΠPaw / SelfPaw 使用；**不是**与 SelfPaw、ΠPaw 并列的第五条产品轨道。  
> **配套**：调研见 `SIO_MMOS_DIKW_Agent_World_Model_And_Semantic_Operation_Layer.md`；场景匹配器见 `scripts/awm_scenario_matcher.py`。

## 1. 产品应该如何定义

### 1.1 先否定三种卖法

| 不要这样定义 | 顾客听到什么 | 为什么失败 |
|--------------|--------------|------------|
| 「我们有更强的 Agent」 | 又一个聊天机器人 | 与 Copilot / Agentforce 同场，无对象世界 |
| 「我们有世界模型大模型」 | 要买算力与视频生成 | 与 Cosmos / Sora 同场，进不了采购单与审批 |
| 「我们做企业本体平台」 | Palantir 平替 | 重平台、长实施、输在品牌与实施军 |

**正确产品定义**：AWM 是 **决策级、可写回的共享世界运行时**。它把组织（或个人）里「有哪些主体、客体、约束、反馈」做成可查询快照，把「想达成什么」做成可计算意图，把「允许做什么」做成封闭动作类型。Agent 是这个世界上的行动者，不是产品本身。

形式：每次工作是一个 SIO 交易。

```
S  Situation  当前世界切片（谁、对什么、状态多新、证据是什么）
I  Intent     目标 + 硬约束 + 成功度量 + 谁的价值
O  Operation  封闭动作序列（查询 / 仿真 / 建议 / 受控执行）
```

### 1.2 对内架构定义 vs 对外价值定义

| 听众 | 定义 |
|------|------|
| 内核工程师 | \(\mathcal{W}=(O,S,M,V)\) + L3 操作表 + 语义操作层 |
| 产品经理 | 共享世界 + 推演台 + 门控写回 |
| 买单的业务负责人 | 「Agent 做事之前，先让我和它看见同一张业务真值表」 |
| 合规/审计 | 「每笔动作有对象、有证据、有审批、可回滚」 |
| 个人用户（SelfPaw） | 「我的目标、关系和待办是一个世界，不是一堆聊天记录」 |

### 1.3 可售卖 SKU（顾客买的是模式，不是「模型」）

| SKU | 顾客语言 | 技术模式 | DIKW 退出门槛 | 价格锚（示意） |
|-----|----------|----------|----------------|----------------|
| **AWM Lens** | 看清世界 | `/query` + `/explain` | I 层：对象能对上系统 ID | 项目制 / 座席 |
| **AWM Stage** | 先演后做 | + `/plan` + `/simulate` | K 层：计划合法率达标 | Lens + 仿真席 |
| **AWM Gate** | 受控改世界 | + `/execute` 审批写回 | W 层：越权=0，回滚可用 | 年费 + 动作量 |
| **Domain Pack** | 开箱场景 | 预置 5–8 对象、10 动作 | 该域 SIO 卡片完整 | 包年模板 |
| **AWM Studio** | 自己建模 | 世界画布 + 动作注册表 | 架构师生效 | 含在企业版 |

默认销售话术：**先卖 Lens，用 Stage 证明价值，用 Gate 收写回溢价。禁止首单卖「全自主 Agent」。**

### 1.4 与四层交付的关系

```
顾客看见的产品
  ΠPaw 工作台 / SelfPaw  →  用世界（操作员、审批人、个人）
  UAS Studio            →  建世界（架构师、领域专家）
  UAS Kernel · AWM      →  跑世界（快照、计划、门控、审计）
```

AWM 对 ΠPaw 是「业务真值与动作契约」；对 SelfPaw 是「个人情境与代理边界」；对 Studio 是「可配置的世界与动作」。三者共享同一 Kernel，避免做成三个互不相认的图谱。

## 2. 面向的客户

### 2.1 买得动、用得上的人（不是「所有要 AI 的企业」）

**理想客户画像（ICP）必须同时满足：**

1. **世界是分裂的**：同一 SKU / 客户 / 工单在 ERP、Excel、聊天里各有一份真相。  
2. **动作有代价**：错一次有钱、有合规、有客户流失，而不是「总结错了再问一次」。  
3. **有主体冲突**：计划、财务、仓、销售、合规不是同一人，需要看见彼此约束。  
4. **愿意承认对象**：至少能说出 5 个核心业务对象和 3 类允许的动作。  
5. **有可观察反馈**：动作之后 24–72 小时内能看到状态变化。

不满足 4 和 5，只卖 Lens，不卖 Gate。

### 2.2 客户分层

| 层 | 组织 | 关键买手 | 关键用户 | 为何买 AWM 而不是 Copilot |
|----|------|----------|----------|---------------------------|
| **P0** | 100–10000 人，运营/供应链/销售运营/客服/合规 | COO / 运营 VP / 风控 | 调度员、审批人、领域架构师 | 要写回与审计，不要又一个侧边栏 |
| **P1** | 有系统但无 Palantir 预算的中型集团 | CIO + 业务一把手 | 流程 owner | 要对象世界，但实施必须 90 天内看见 Stage |
| **P2** | 专业服务 / 内部平台团队 | 企业架构、知识工程 | Studio 用户 | 要可复制 Domain Pack，而不是项目制本体咨询 |
| **P3** | 知识工作者、创始人、个人 AGI | 本人 | SelfPaw 用户 | 要「我的世界」跨应用一致，而不是会话记忆 |

**明确不作为首年 ICP**：纯内容生成团队；只要「接入 GPT」的 IT 项目；没有业务对象 owner 的「AI 中台」采购；把世界模型理解成自动驾驶/视频大模型的硬件团队（那是 Cosmos 场）。

### 2.3 三类角色的体验承诺

| 角色 | 打开产品后 30 秒应感到 |
|------|------------------------|
| **操作员** | 「这就是我今天要盯的世界，不是对话框」 |
| **审批人** | 「我只看到要我签字的动作、金额、不可逆点和证据」 |
| **架构师** | 「对象、关系、动作、规则在一张图上，版本可 diff」 |
| **审计** | 「任意一笔动作能回到对象、意图、模型版本、谁批的」 |

若这四类人被塞进同一个 Chat，产品已经输了。

## 3. 面向的场景

### 3.1 场景匹配原则（SIO 打分，而不是行业名打分）

行业标签（零售、制造、金融）只是包装。**匹配的是结构：**

| SIO 维 | 高匹配信号 | 低匹配信号 |
|--------|------------|------------|
| **S 情境** | ≥3 类主体、对象有系统 ID、有反馈通道 | 「我们主要是文档和会议」 |
| **I 意图** | 有硬约束（预算、SLA、合规、库存下限） | 「提高效率」无度量 |
| **O 操作** | 有写回系统，且部分动作不可逆 | 只要生成 PPT/邮件 |
| **DIKW** | 至少 D 能接上 2 个源；I 可做实体对齐 | 数据在私人盘且无 ID |

高匹配场景（P0 先做）：

| 场景 | S | I | O | 90 天价值 |
|------|---|---|---|-----------|
| 库存补货 / 缺货与积压 | 仓、SKU、供应商、计划 | 服务水平 vs 预算 | 采购单、调拨 | 缺货率下降、超采拦截 |
| 企业销售 OS（线索→报价→审批） | 客户、机会、审批人 | 折扣纪律、毛利 | 报价、锁价 | 违规折扣下降、周期缩短 |
| 客服升级与工单闭环 | 客户、工单、知识、座席 | SLA、授权边界 | 改状态、赔付、升级 | 误赔拦截、首次解决率 |
| 招聘闭环 | 岗位、候选人、面试官 | 合规、编制 | 推进阶段、offer | 漏人/越权 offer 下降 |
| 个人任务世界（SelfPaw） | 我、关系人、项目、日历 | 目标与精力约束 | 代理发送、改日程 | 跨应用不一致下降 |

刻意后置：工厂物理孪生、自动驾驶、纯研发代码 Agent（各有更强专用竞品）。AWM 可作它们的**语义门面**（对象与权限），不要自称物理引擎。

### 3.2 反匹配（礼貌拒绝或降级）

- 「先做完全自主，三个月替代一个部门」→ 降级为 Lens，并写出 Gate 的数据前提。  
- 「没有主数据，先让 LLM 抽一个知识图谱就写 ERP」→ 拒绝 Gate；GraphRAG 只进待确认池。  
- 「我们要一个能聊天的数字员工」→ 这是 Agent 壳，不是 AWM；转 ΠPaw 轻量座席，不承诺世界一致。

可执行匹配：`python3 scripts/awm_scenario_matcher.py --brief examples/semantic-operation-layer/briefs/replenishment_brief.json`

## 4. 交付的内容与价值

### 4.1 顾客合同里应出现的交付物（Avoid「交付一个模型」）

| 交付包 | 内容 | 验收 |
|--------|------|------|
| **世界骨架** | 5–8 个核心类、关系、身份规则 | 对象能链到源系统 ID |
| **动作注册表** | ≤10 个动作：IO、前置、效果、风险、回滚 | 未注册动作必失败 |
| **SIO 工作台** | 情境条、意图作曲、操作时间线 | 任意计划可 explain |
| **推演台** | Now vs Projected 分屏，禁止把预测当事实 | 仿真不改生产 |
| **门控** | 查询/仿真/建议/执行分权；审批托盘 | 无审批不能写中风险动作 |
| **连接器** | 只读源 + 受控写回适配器 | 写回走 Action，不走裸 SQL |
| **审计包** | 谁/何时/凭何/图 diff/模型与提示版本 | 抽检 10 笔可还原 |
| **DIKW 看板** | 覆盖、新鲜、计划合法率、越权、回滚、业务 KPI | 作为是否升级 SKU 的门槛 |
| **Domain Pack** | 该场景的模板世界 + 金样本测试 | pytest / 回放通过 |

### 4.2 价值主张（按角色可引用的句子）

- **对 COO**：同样的缺货决策，从「群里对拍」变成「共享快照上的受控采购」。  
- **对 CFO**：超预算与不可逆动作默认升级，而不是靠模型「注意一下」。  
- **对 CIO**：Agent 不再每人一套提示词连生产；对象权限是唯一边界。  
- **对操作员**：先看世界，再看建议；点「演一遍」比点「就这么办」更安全、也更快。  
- **对个人用户**：目标、人和待办不会在下一个会话里消失或互相矛盾。

价值度量不要用「满意度」。P0 场景用：决策周期、约束违反率、写回成功率、回滚率、缺货/违规折扣/误赔等业务量。

### 4.3 价值实现路径（与 SKU 对齐）

```
第 1–4 周  Lens   看见分裂的世界（对象对不上就暴露，这本身就是价值）
第 5–8 周  Stage  用仿真证明「若按此动作，风险/成本会怎样」
第 9–12 周 Gate   一条低风险写回 + 一条中风险审批，形成审计样本
之后       Pack   复制到第二个仓 / 第二条产品线，而不是重做本体
```

## 5. 相比竞争产品的优劣

比较的是 **「谁拥有可操作世界」**，不是谁的模型更大。

| 竞品 | 它真正卖的 | 它强在 | 它弱在 | AWM 怎么打 |
|------|------------|--------|--------|------------|
| **Palantir Ontology / AIP** | 企业决策孪生 + 动作 + 安全 | 实施方法论、OAG、写回、安全模型 | 重、贵、封闭、Agent 不是一等公民 | 学其 Action+安全；用更轻的 SIO 交易与双轨 AGI 打「90 天 Stage」 |
| **Salesforce Agentforce** | CRM 预置本体上的数字员工 | 预置对象、分发、Trust Layer | 锁定 CRM；跨 ERP/仓弱 | 做跨系统对象世界；Pack 对准销售 OS 但不做 CRM 替身 |
| **Microsoft Copilot / Graph** | 工作图 + 连接器 | 入口与覆盖 | 本体要客户自建，写回浅 | 不拼入口；拼「硬约束 + 对象级门控」 |
| **Neo4j GraphRAG / 开源图谱 RAG** | 从文本看见结构 | 全局问题、开源 | 默认只读、类型漂移 | 把它当 D→K 管道，不当 Action 层 |
| **LangGraph / AutoGen / SK** | 编排 | 开发者生态 | 无共享世界，权限在 tool 名 | 编排只做器；世界与权限在 AWM |
| **Bedrock Agents + Neptune** | 云上工具+图 | 集成速度 | 无统一对象生命周期 | 用云当存储，不把 IAM 当业务本体 |
| **NVIDIA Cosmos / 驾驶 WM** | 物理未来预测 | 仿真与生成 | 不是采购单与审批 | 只作 PREDICT 插件，不进 P0 报价单 |
| **传统数字孪生（MES/工厂）** | 物理镜像 | 设备与工艺 | 缺主体博弈与语义动作 | 互补：它们管物理，AWM 管决策对象 |
| **Chat 数字员工** | 对话自动化 | 上线快 | 幻觉写系统、不可审计 | 用 Lens 替代「先聊天」；Gate 才允许动手 |

**我们相对优势（若执行克制）**

1. **SIO 是产品原子**：每次交互都是情境–意图–操作，不是线程里的散文。  
2. **预测与事实分离**：Stage 与 Gate 分权，这是 Palantir 有、Copilot 弱、开源 Agent 几乎没有的。  
3. **双轨同一世界**：个人（SelfPaw）与组织（ΠPaw）可投影同一 Kernel，竞品通常只做一边。  
4. **知识即配置**：Domain Pack 让业务改动作契约不必改代码。  
5. **轻于 Palantir**：先 8 个对象、10 个动作，而不是企业全量本体工程。

**我们相对劣势（必须写进销售纪律）**

1. 没有二十年对象库与实施军团。  
2. 没有 M365 / Salesforce 级分发。  
3. 物理世界模型不是主场。  
4. 仓库内世界模型仍有占位与简化运行时，Gate 的生产硬度要靠连接器与治理补齐。  
5. 若销售把 AWM 讲成「更聪明的聊天」，优势全部消失。

**竞争策略一句话**：不与 Palantir 拼全平台，不与 Copilot 拼入口，不与 Cosmos 拼像素；在 **跨系统对象 + 封闭动作 + 90 天可演示的推演台** 上做标准切口。

## 6. 场景如何匹配（销售与实施共用一张卡）

### 6.1 90 秒准入（五个问题）

1. 这件事里，**谁**会推动、阻碍或必须签字？（主体 ≥ 2）  
2. 改的是哪个**带 ID 的对象**？（客体可指认）  
3. 怎样才算成功？哪条线**绝对不能破**？（意图可计算）  
4. 系统里今天**实际能执行**哪三件事？（操作封闭）  
5. 做完之后，**多久能看见**世界变了？（反馈）

五个都能答：进入匹配器打分。答不出 2 或 4：只配 Lens，并启动对象治理，而不是启动 Agent 项目。

### 6.2 匹配输出（实施启动包）

匹配器输出必须包括：

- 推荐 SKU（Lens / Stage / Gate）  
- 推荐 Domain Pack  
- 建议的第一批对象（≤8）与动作（≤10）  
- 进入的 UX 模式（见 §7）  
- 明确的「本期不做」  
- DIKW 缺口（缺源、缺 ID、缺审批人）

这避免「先上 Agent 再找世界」。

### 6.3 场景 × SKU 决策表

| 条件 | SKU |
|------|-----|
| 有对象 ID，无写回需求 | Lens |
| 有约束与可仿真效果，写回政治上敏感 | Stage |
| 有审批人、补偿动作、反馈 SLA | Gate |
| 客户坚持全自主且无补偿动作 | **不签 Gate**；书面降级 |
| 个人侧、跨日历邮件任务 | SelfPaw Lens → 低风险 Gate（发草稿，不直接群发） |

## 7. 场景匹配后的极致体验设计

体验原则：**世界是舞台，对话是灯光。** 聊天可以存在，但不能当首页。

### 7.1 体验原则（不可谈判）

1. **World-first**：默认页是世界画布 + 情境条，不是输入框。  
2. **对象必具名**：界面禁止出现无 ID 的「那个仓库」「这个客户」。  
3. **Now ≠ Maybe**：当前事实与推演结果分色、分栏，预测带虚线。  
4. **意图可见**：目标、硬约束、成功度量始终在顶栏，改约束即重编译计划。  
5. **动作是卡片不是句子**：每张卡有风险色、前置、效果、谁批、能否撤销。  
6. **失败是类型错误**：校验失败显示「未注册动作 / 悬空引用 / 超预算」，不显示一篇道歉。  
7. **审批是托盘不是 IM**：审批人看到的是差量，不是聊天记录。  
8. **做完必回看**：执行后把预测与观测叠在一起（OBSERVE），这是「绝佳」的来源——世界会说话。  
9. **角色换肤，世界不换**：操作员、审批人、架构师看同一 \(\mathcal{W}\) 的不同投影。  
10. **空状态教匹配**：新租户不是空白画布，而是 90 秒五问 + 推荐 Pack。

### 7.2 信息架构（四个角色四套壳、一个世界）

```
┌─ 情境条 Situation Strip ──────────────────────────────────┐
│ 世界 freshness · 缺口 · 当前主体 · 硬约束芯片              │
├──────────────┬─────────────────────────────┬──────────────┤
│ 世界画布      │  SIO 工作区                 │ 证据抽屉     │
│ Subjects     │  Intent 作曲                │ 来源/置信    │
│ Objects      │  Operation 时间线            │ 图 diff     │
│ Relations    │  Now | Projected 分屏        │ 审计        │
├──────────────┴─────────────────────────────┴──────────────┤
│ 门控托盘：允许 / 需审批 / 已拦截 · 一键 explain            │
└───────────────────────────────────────────────────────────┘
对话入口：右下「问这个世界」，上下文锁定当前切片，禁止漂到无对象闲聊。
```

### 7.3 关键功能（按体验高潮，而不是按模块清单）

**① 90 秒场景匹配（Onboarding）**  
五问之后，画布上已经出现推荐的 5 个对象和 3 个动作虚影，用户只做「确认 / 改名 / 删掉」，不从零拖拽。这是与 Palantir「先上本体课」和 Copilot「先聊天」的差异点。

**② 情境条（Situation Strip）**  
永远回答：这是谁的世界、数据多新、缺哪类对象、哪条反馈在超时。缺口用琥珀色，不藏在设置里。Lens 的核心快感是「原来我们对不上」。

**③ 意图作曲（Intent Composer）**  
目标一句话 + 约束芯片（预算、期限、SLA）+ 成功度量。芯片可点、可冲突检测（「服务水平 99%」与「零库存」并排变红）。改芯片 = 重编译 O，而不是再聊一轮。

**④ 操作时间线（Operation Timeline）**  
三张卡：查询（绿）→ 创建采购单（琥珀、需审批）→ 通知（绿）。拖拽只在合法动作集内；试图加入「删库」会弹类型错误。悬停显示前置与效果。

**⑤ 推演分屏（What-if Stage）**  
左 Now：on_hand 40。右 Projected：expected 130，缺货风险 18%→0%。中间一条「未写入」缎带。用户的高潮是 **看见未来且知道它还不是真的**。

**⑥ 审批托盘（Gate Tray）**  
审批人默认不进画布。只看到：对象、金额、不可逆、证据三条、一键同意/驳回/要补证据。手机可用。这是 CFO/合规愿意日活的原因。

**⑦ Explain 不是作文**  
结构固定：因为情境 S（引用对象）+ 因为意图 I（引用约束）+ 所以动作 O（引用注册表）+ 被哪条规则拦住或放行。可复制到审计包。

**⑧ 回放与打脸（Feedback Pulse）**  
T+反馈周期：预测风险 vs 实际出库。打脸是产品功能：校准条进入 DIKW 看板，驱动 Stage 是否升 Gate。

**⑨ 架构师 diff**  
对象/动作的 Git 式 diff。业务改安全库存规则，操作员立刻在约束芯片上看到，无需发版说明。

**⑩ 个人侧投影（SelfPaw）**  
同一套 SIO：今天的「我、会议、承诺、精力」。Gate 默认是「生成草稿 / 改我的日历」，群发升级。世界画布是时间线而非仓网。

### 7.4 按场景切换的 UX 模式（匹配器直接指定）

| 模式 | 何时 | 首页 | 主按钮 | 禁止 |
|------|------|------|--------|------|
| `lens` | 对象刚对齐 | 画布 + 缺口 | 「解释这个对象」 | 执行 |
| `stage` | 有约束可算 | 分屏推演 | 「演一遍」 | 写生产 |
| `gate` | 有审批与回滚 | 时间线 + 托盘 | 「提交审批」 | 跳过托盘的 API |
| `architect` | 建模 | 注册表 + diff | 「发布世界版本」 | 直接连生产写回 |
| `selfpaw` | 个人 | 日程世界 | 「放入我的世界」 | 静默外发 |

匹配器输出 `ux_mode`，Studio / ΠPaw 按此切换壳，不让实施自己发明首页。

### 7.5 微交互与文案（体验质量藏在这里）

- 主按钮文案随模式变：看 / 演 / 提交审批 / 发布世界；永远不要「智能执行」。  
- 风险色只用于动作卡：绿查询、琥珀需人、红不可逆。  
- 新鲜度：<1h 实心，>SLA 呼吸灯。  
- 空搜索：不返回网页散文，返回「世界里没有这个 ID，要把它登记为对象吗？」  
- 快捷键：`E` explain，`[` `]` 上一步下一步动作，`Space` 演一遍。  
- 无障碍：审批托盘先于画布可读；色不作为唯一风险通道。

### 7.6 体验成功标准（可进评审）

| 角色 | 5 分钟任务 | 通过标准 |
|------|------------|----------|
| 操作员 | 从缺口找到缺货 SKU 并生成计划 | 不打开聊天也能完成 |
| 审批人 | 在托盘批准或驳回一笔采购 | 不需要理解本体 |
| 架构师 | 增加一个动作类型并看到时间线多一张卡 | 无需发版 |
| 新客户 | 五问后得到推荐世界虚影 | <90s |

做不到这四条，不叫体验绝佳，只是多了一个带图谱的 Chat。

## 8. 90 天产品切片（把定义收成可做的范围）

只做一个 Domain Pack（建议补货或销售 OS）：

1. Lens：世界画布 + 情境条 + 对象 ID 对齐报告。  
2. Stage：SIO 时间线 + Now/Projected。  
3. 匹配器：五问 → SKU + ux_mode。  
4. Gate：单动作审批托盘（可先人工，再接系统写回）。  
5. 看板：计划合法率、拦截次数、仿真未写生产（恒为真）。

超出此范围的「全企业本体 / 全自主 Agent / 物理仿真」一律列为非目标。

## 9. 假设与校准

| 假设 | 类型 | 若为假则 |
|------|------|----------|
| 顾客愿先买「看清」再买「动手」 | 关键 | 改成按动作量订阅，但 Gate 仍需门槛 |
| 8 对象/10 动作足够证明价值 | 关键 | 该场景不配 AWM，转回 Copilot 类 |
| 审批人接受独立托盘 | 次要 | 嵌进已有 OA，但差量结构不变 |
| 个人侧与组织侧可共享 Kernel | 待验证 | SelfPaw 先用独立投影，协议仍是 SIO |

若你的 SIO-MMOS 定义与本文同构声明不同，替换映射即可，SKU 与 UX 模式不必重做。

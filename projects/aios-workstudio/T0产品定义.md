# AIOS WorkStudio · T0 产品定义

> 地位：本目录的产品契约。争议时服从 `docs/AI_PRODUCT_CHARTER.md`。  
> 版本：T0.3 · 2026-08-22  
> 配套：`T0竞争焦点与领先路径.md` · `T1-WorkStudio详细设计.md` · `T1-场景态与执行态.md` · `T1-CapabilityHub详细设计.md`

---

## 一句话

企业里的岗位主体，先在**场景态工作台**用 DIKW 看见过关张力并签发任务，再在**执行态**（Explore / Builder / Runtime）把任务编译成可追责的工作；后台是能力中枢。产品是**法则编译器**，不是更好的 AI 同事。

---

## 1. 场景定位

| 面 | 是什么 | 不是什么 |
|----|--------|----------|
| **用户前台** | 企业 AI 工作台：Copilot + 智能化岗位（流程） | WorkBuddy / 千问办公的功能仿制；聊天壳冒充工作台 |
| **能力后台** | AI 能力中枢：知识语义、能力组件、可执行商业世界模型 | 专家人设市场；RAG 片段墙；Agent 编制墙 |

两条腿必须同时成立。只有前台 = 又一个办公 Agent。只有后台 = 又一个没人用的知识平台。

---

## 2. 产品用户

以企业用户为主，两条环位，**不混权**。

| 角色 | 要完成的工作 | 产品形态 | 环位 |
|------|----------------|----------|------|
| 员工 / Copilot | 把当前任务做成可交差的产物 | 意图入口 + 证据盒 + 本地/授权文件 | On loop 可加速；高影响必须升级 |
| 岗位主体（流程 Owner） | 把一条价值流跑成可审计闭环 | 五维世界模型首屏 + 7 步状态 | 默认 In the loop · G3 |
| 管理者 / 指挥席 | 看偏差、批承诺、回收收益 | 对冲视图（应当 vs 事实），不是 KPI 墙 | Above loop 只看例外 |

禁止：把个人 Copilot 的记忆、通道、承诺权直接做成组织生产动作。

---

## 3. 核心价值（T0 只认这四句）

1. **知识驱动的组织能力**：岗位法则、Skill、门禁写在显式知识里，改完即跑；行为不藏进权重和一次性 prompt。  
2. **场景价值流闭环**：单点润色、单点周报不是产品。必须走到输出与可归因收益。  
3. **人机统一语言**：五维（空间 / 时间 / 主体 / 客体 / 感知—行动—反馈）是人、Copilot、系统的共同语法。缺一维则任务未建模。  
4. **业务元认知**：系统能判断「这件事该快走、该加深、还是该停手核实」，并适应不同业务，而不是为每个行业重做一套专家皮肤。

竞争力不来自专家数量、Skill 数量、连接器数量——那是巨头的面积战。竞争力来自：**同一套语言能否把任意业务编译成可执行闭环。**

## 4. 对标与分层（禁止平面对打）

| 层 | 对标 | 我们学什么 | 我们不学什么 |
|----|------|------------|--------------|
| 用户前台 | WorkBuddy、千问办公、Codex | 可验收产物、IM 入口、按需 Skill、嵌入工作对象的循环 | 「AI 同事」人设、专家团堆砌、空白对话框当主路径 |
| 能力后台 | 知识图谱、能力组件、商业世界模型 | 显式法则、组件化能力、模型提议 / 平台执行 | 把图谱当世界；把组件当产品；让 LLM 持生产凭证 |

前台对用户像工作台，后台对组织像操作系统。对外一句话若说成「对标 WorkBuddy」，T0 失败。

## 5. 产品结构（前台 × 后台）

```
用户前台（WorkStudio）
  场景态 Scene     详细设计：T1-场景态与执行态.md
    Pack         经营 | 项目 | 投研（T0 只深经营·人才流）
    五模块       驾驶舱 · 价值流 · Todo/PMO · 策略资产 · 升维学习
    DIKW         Data→Insight→Task（带五维）→ 进入执行态

  执行态 Execute   详细设计：T1-WorkStudio详细设计.md
    Explore      探索研究（AI 任务）→ ThemePack
    Builder      应用化构建（AI 任务）→ AppRelease
    Runtime      运行治理（AI 任务）→ 收益回场景

能力后台（Capability Hub） 详细设计：T1-CapabilityHub详细设计.md
  世界模型     draft | compiled | live 三寿命
  Skill 协议   discover → cite → install → enable → execute
  能力组件     cs.* ；场景态/Explore/Builder 禁写生产
  Harness      同一循环 × 剖面（scene|explore|builder|runtime）
  治理         租户 / RBAC / 双轨 / G0–G6 / 审计
  演化         升维学习 → ChangeSet → 新法则 / 策略资产
```

场景态是用户首页；Explore / Builder / Runtime 是任务执行态，不是三个内容工作台。

## 6. T0 做 / 不做

**做**

- 选定 **一条** 企业价值流做透（默认：招聘短名单，已有 World Model Studio 原型；可替换为同等闭环的销售/工单，但同时只许一条）。  
- 员工 Copilot 与岗位闭环共用同一世界模型，分权不分叉。  
- 输出结构固定：意图理解 · 所用知识 · 证据 · 不确定点 · 建议 · 门禁 · 回滚。  
- Skill 按协议加载；项目法则进显式知识。

**不做**

- 不做数字员工墙、专家团市场、通用「什么都能聊」。  
- 不做全自动淘汰 / 静默对外承诺 / Agent 直连生产库。  
- 不把聊天历史当业务状态。  
- 不与巨头比 Skill 数量、积分价格、IM 覆盖面。

---

## 7. 成功标准（T0 北极星）

北极星唯一：**质量调整后的岗位闭环成功率**（产出被岗位主体接受、证据接地、无越权、可回滚）。

输入指标可多：任务完成时延、未接地陈述占比、法则被修订次数、跨系统动作成功率。  
禁止用 Token 消耗、对话轮次、专家安装数代替北极星。

反例即失败：能力只在 JSON 与脚本里，业务用户感觉不到；或感觉到了，但不敢拿去交差。

---

## 8. 体验不变式（过不了不叫本产品）

1. 首屏是当前决策的低维结构（谁、对谁、何时、何法则、何反馈），不是 Agent 列表。  
2. 先解释，再建议，再动作。  
3. 不确定必须显式；「不知道」优于伪装确定。  
4. 改知识即改行为，无需发版。  
5. 个人轨加速，经营轨升级；禁止静默混权。

# T1 · 场景态 × 执行态

> 分层修正：Explore / Builder / Runtime 是 **AI 任务执行态**，不是用户日常首页。  
> 用户首页是 **场景态工作台**（经营 / 项目 / 投研…）。场景用 DIKW 从数据产生洞察，洞察产生任务，任务进入执行态。  
> 服从：宪章道-3（驾驶舱不得变成 KPI/Agent 墙）· `T0产品定义.md` · SIO-MMOS · DIKW（`docs/THEORY_SYSTEM.md` §4.4）  
> 版本：T1.1 · 2026-08-22

---

## 1. 一句话

**场景态看见并决定「过哪一关」；执行态把关编译成可追责的工作。**  
两者共用世界模型与 Capability Hub，禁止做成两套产品。

```
场景 Pack（经营 | 项目 | 投研 | …）
  └─ 五大模块（驾驶舱 · 价值流 · Todo/PMO · 策略资产 · 升维学习）
        DIKW：Data → Information → Knowledge → Wisdom
              ↓ 洞察落地为 Task（带五维 + 证据 + 建议环位）
执行态  Explore | Builder | Runtime
              ↓ 产物 / 审计 / 收益
        升维学习：回写策略资产（K）与法则（W）
```

---

## 2. 为什么必须分层

上一版把 Explore/Builder/Runtime 当成 WorkStudio 的「三种产品场景」，会把用户丢进方法论运行时。那是构建者和 Agent 的工作面，不是经营者打开产品的第一眼。

| | 场景态 Scene | 执行态 Execute |
|--|--------------|----------------|
| **用户问** | 组织现在卡在哪？下一个过关动作是什么？ | 这个任务怎么研究 / 编成应用 / 带权跑完？ |
| **一级对象** | ScenePack · Insight · Todo | ThemePack · AppRelease · AppInstance |
| **时间** | 持续在场（驾驶舱/价值流） | 有界任务（一个 turn 链） |
| **DIKW** | 上行：D→I→K→W 出洞察 | 下行：W/K 压缩进任务再落到 Data/动作 |
| **失败** | 堆面板、不下钻、洞察不变任务 | 从空白对话框开工、没有场景上下文 |

宪章对照：方案 B「经营驾驶舱 = KPI + Agent 编制墙」被否，否的是 **用面板冒充世界模型**。本层允许驾驶舱作为 **Wisdom 的透镜**：只暴露当前梯度上的张力，下钻才展开，禁止编制墙。

## 3. 五大方法论 × 五大模块

方法论不是五套互斥宗教，是同一编译器的五个操作面：

| 方法论 | 在 WorkStudio 的职责 |
|--------|----------------------|
| **道德势术器** | 道/德约束、势的张力、术的路径、器的触点 |
| **SIO-MMOS** | S 情境 → I 干预 → O 结果 → 监测/修正/优化/放大 |
| **DIKW** | 数据↔智慧双向：价值回路上行、压缩回路下行 |
| **价值闭环 7 步** | 执行态主路径；场景态负责把 7 步接到真实岗位对象 |
| **世界模型五维** | 任务未建模的否决条件；场景洞察必须能投影到五维 |

| 产品模块 | 方法论映射 | 核心能力 | 产出 |
|----------|------------|----------|------|
| **1. 经营驾驶舱** | DIKW Wisdom + 器 + 势 | 组织梯度 × 客户/对象梯度；六维评分是 **下钻手柄** 不是墙 | Insight（W） |
| **2. 价值流场景** | SIO-MMOS **S** + 法 | LTC（或本 Pack 的主价值流）五阶段、四级穿透：Dashboard → List → 360 → Todo | Situation 对象 |
| **3. Todo PDCA/PMO** | SIO-MMOS **I** + 法 | Plan-Do-Check-Act；跨团队依赖与环位 | Task → 执行态 |
| **4. 策略资产沉淀** | UAS 知识层 + DIKW Knowledge | 策略分类、效果回收、自反馈公理 | Knowledge Pack |
| **5. 升维学习迭代** | SIO-MMOS 全闭环 + DIKW 跃迁 | D→I→K→W→Meta；执行态收益回流 | ChangeSet / 新法则 |

模块是 **每个 Scene Pack 都有的操作系统**，不是五个独立 App。换 Pack 只换客体与价值流阶段定义，不换模块。

## 4. Scene Pack（用户场景态的实例）

Pack = 领域世界模型的情景化，不是皮肤。

| Pack | 对象梯度 | 主价值流（LTC 类比） | T0 |
|------|----------|----------------------|----|
| **经营管理工作台** | 组织梯度 × 客户/人才梯度 | 获客到现金 / 人才到到岗 | **默认演示 Pack**（人才短名单） |
| **项目管理工作台** | 组合 × 项目 × 里程碑 × 任务 | 立项到验收 | P1 |
| **金融投资工作台** | 组合 × 标的 × 因子 × 仓位 | 研究到下单到复核 | P1 |

新 Pack 准入：必须声明五维、价值流阶段、六维评分含义、Todo 如何投影到执行态。缺一不准上架。禁止只换标题的「XX 工作台」。

## 5. DIKW 如何变成任务

**价值回路（场景态，上行）**

```
Data        客体记录、事件、审计、KPI 原始点
   → Information   差异/张力（势）：未接地率升高、阶段滞留
   → Knowledge     结构化解释：对照法则 Pack
   → Wisdom        过关判断：这件事该加深研究 / 该编应用 / 该带权执行
   → Task          带：五维草稿、证据、不确定点、建议执行态、门禁
```

**压缩回路（执行态结束，下行）**

```
Wisdom/法则 → 写入 compiled WM → Runtime 动作变成新 Data → 升维模块决定是否跃迁 K/W
```

Task 对象最小集：

```yaml
task_id: tsk-...
pack: ops | pmo | invest
source: cockpit | value-stream | todo | learn
insight_id: ins-...
dikw_level: W          # 从哪一层落下
suggested_exec: explore | builder | runtime
world_model_draft: { space, time, subjects, objects, feedback }
evidence: []
uncertainties: []
gate_hint: G0-G3
```

路由：

| 洞察类型 | 进入 |
|----------|------|
| 法则不够 / 事实冲突 / 无现成 Skill | **Explore** |
| 方案已清、要固化成可交接应用 | **Builder** |
| 应用已在、只要带权跑完一步 | **Runtime** |

禁止：驾驶舱按钮直接 `cs.*` 写生产（仍要 Runtime + 门禁）。禁止：Todo 变成聊天句，丢失五维。

## 6. 四级穿透（价值流模块）

以经营 Pack 的人才流为例（T0 标杆，不铺销售皮肤）：

```
L0 Dashboard   梯度与六维张力（Wisdom 透镜）
L1 List        本阶段客体列表（Information）
L2 360         单客体 ought/is + 法则对照（Knowledge）
L3 Todo        PDCA 项，可签发 Task（Intervention）
```

LTC 五阶段在本标杆映射为：需求 → sourcing → 短名单 → onsite → 到岗。其他 Pack 替换阶段名，穿透深度不变。

## 7. 与执行态的接口

场景态只调 Hub 的场景语义；执行态仍用既有 `hub.theme.*` / `hub.app.*` / `hub.instance.*`。

```
hub.scene.pack.list | open
hub.scene.insight.list | drill
hub.scene.task.issue      # 产出 Task，指定 suggested_exec
hub.exec.open(task_id)    # 打开 Explore/Builder/Runtime 并注入五维
hub.exec.return           # 产物挂回 Todo Check/Act，进升维与策略资产
```

执行态页脚「回场景」必须带着 Instance/Theme 引用，禁止复制聊天当交接。

---

## 8. 体验不变式（场景态）

1. 驾驶舱默认只显示 **当前主张力** + 可下钻的六维手柄，不铺 Agent 列表。  
2. 洞察必须能指出五维；不能指出则只是装饰图表。  
3. Todo 签发 Task 时必须选择执行态；系统可建议，人可改。  
4. 升维学习产生的法则回写走 ChangeSet，与 Runtime 相同，禁止静默。  
5. 换 Pack 不得丢失执行中的 Task；Task 带着 pack_id。

## 9. T1 范围

**做**：经营 Pack + 五模块壳 + 人才价值流四级穿透 + 一条洞察签发到 Explore（短名单未接地）。  
**不做**：三个 Pack 同等深度；驾驶舱实时数仓；PMO 全功能。

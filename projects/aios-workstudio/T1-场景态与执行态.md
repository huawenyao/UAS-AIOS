# T1 · 场景态 × 执行态（业务语言版）

> 用户首页是**作战台**（今日必办 / 客户作战室 / 团队指挥舱），不是技术术语。  
> 执行态是**AI 帮你干活**（研究 / 构建 / 运行），不是方法论名词。  
> 服从：宪章道-3（驾驶舱不得变成 KPI/Agent 墙）· `T0产品定义.md`  
> 版本：T1.2 · 2026-09-02 · **业务语言版**

---

## 1. 一句话

**作战台看见并决定「干什么」；执行态把关编译成「怎么干」。**

```
作战台（我的首页）
  ├─ 今日必办：3 个客户要跟进，2 个审批要催
  ├─ 客户作战室：点进客户，看 360，确认下一步
  └─ 团队指挥舱：管理者看全局，调配资源
        ↓ 签发任务
执行态（AI 干活）
  ├─ 研究：这个客户为什么卡？怎么破局？
  ├─ 构建：把这个打法固化成可复用流程
  └─ 运行：带权执行，写 CRM，回写状态
        ↓ 结果回写
作战台：任务完成，客户状态更新
```

---

## 2. 为什么必须分层（业务语言版）

| | 作战台（我的首页） | 执行态（AI 干活） |
|--|------------------|------------------|
| **用户问** | 我今天该干什么？哪个客户要丢？ | 这个任务怎么研究 / 怎么固化 / 怎么执行？ |
| **看到什么** | 客户列表、今日必办、团队状态 | 任务详情、执行进度、结果反馈 |
| **操作什么** | 确认动作、派任务、催审批 | 研究、构建、运行 |
| **时间** | 持续在场（每天打开） | 有界任务（一个任务链） |
| **失败** | 堆图表、不告诉该干嘛 | 从空白开始、没有上下文 |

## 3. 作战台五大模块（业务语言版）

| 模块 | 用户问的问题 | 看到什么 | 能干什么 |
|------|-------------|---------|---------|
| **今日必办** | 我今天该干什么？ | 按紧急程度排序的任务卡片 | 确认、调整、转派 |
| **客户作战室** | 这个客户什么情况？ | 客户 360、卡点分析、下一步动作 | 确认执行、调整策略 |
| **团队指挥舱** | 团队业绩怎么样？ | 漏斗分析、人员状态、资源调配 | 调配客户、支援请求 |
| **线索池** | 线索质量怎么样？ | MQL 列表、分配状态、转化追踪 | 分配线索、跟进提醒 |
| **策略资产** | 以前什么打法有效？ | 成功案例、话术库、最佳实践 | 引用、复用、迭代 |

## 6. 执行态（AI 干活）

### 6.1 三种执行模式

| 模式 | 什么时候用 | AI 干什么 | 人干什么 |
|------|-----------|----------|---------|
| **研究** | 客户为什么卡？怎么破局？ | 分析数据、找原因、给方案 | 确认方案、调整策略 |
| **构建** | 这个打法要固化成流程 | 把方案编成可复用流程 | 审核、发布 |
| **运行** | 任务要执行，写 CRM | 带权执行、写系统、回写状态 | 监控、审批 |

### 6.2 从作战台到执行态

```
作战台：客户A 卡在拜访阶段
  ↓ 签发任务
执行态选择：
  ├─ 研究：为什么卡？怎么破局？
  │   → AI 分析数据，给出破局方案
  │   → 人确认，进入下一步
  │
  ├─ 构建：把这个打法固化成流程
  │   → AI 把方案编成可复用流程
  │   → 人审核，发布到团队
  │
  └─ 运行：直接执行任务
      → AI 约拜访、写 CRM、发邮件
      → 人监控，审批关键节点
  ↓ 结果回写
作战台：任务完成，客户状态更新
```

## 7. 体验不变式（业务语言版）

1. **打开就知道干什么**：首页就是今日必办，不需要找  
2. **客户状态一眼清**：红绿灯 + 一句话说明  
3. **下一步动作 AI 给**：确认或调整就行  
4. **执行结果自动回**：不需要手动更新  
5. **团队协作不费劲**：任务派发、状态同步、一键完成

## 1. 剥离复杂性后的本质

### 1.1 一句话价值

**让我（和你）用极小的生命材料，留下一个「只属于此刻、可被理解、可被撤回」的私人仪式。**

用户买的不是 AI、不是心跳、不是 Vault、不是 Consent Center。  
用户买的是一种感受：

> **「我被看见了——而且没有被分析、催促或占有。」**

体验内核四个字：**被看见的仪式。**

成功瞬间不是「生成完成」，而是用户心里那句：

> **「这就是我 / 这就是我们。」**

理想结果可以是：完成一次仪式后离开。时长与打开次数不是价值本身。

### 1.2 与替代品的本质差

| 替代品给人的感觉 | LifeWake 必须给人的感觉 |
|---|---|
| 被测量 / 被评分 | 被理解，不被定义 |
| 被推荐 / 被填满 | 被适时赠予一件有限作品 |
| 被连接成监控 | 双方自愿共创，可随时撤回 |
| 被催促回来 | 允许沉默；稀缺保护意义 |

### 1.3 产品语法（唯一母句）

```text
授权的生命材料
  → 可解释的创作
  → 合适的时机（可 defer）
  → 私人 / 共同仪式
  → 主权记忆（可保存 / 删除 / 撤回共享）
  → 受控演化（反馈 → ChangeSet，不自动改人）
```

## 2. 单点击穿的用户体验

不以功能入口组织产品，而以一次可完成的击穿动作组织首体验。

### 2.1 单人击穿（首发 Aha）

**入口文案级简单：**「为此刻做一件事」

```text
选一点属于我的材料
  → 等一下（允许空、可离开）
  → 揭晓一件作品 + 「为什么是你」
  → 「有触动 / 不对 / 删掉」
```

**验收（体验，不是工程）：**

1. 三步内看懂：为何是我、为何是现在、用了什么。
2. 同时只有一件可揭晓仪式；无无限流填空。
3. 删除与保存同等清晰；负反馈不要求解释。

### 2.2 双人击穿（可传播 Aha）

**入口：**「和 TA 一起留下这一刻」

```text
A 发起邀请（不上传对方数据）
  → B 独立看见目的 / scope / 期限并同意或拒绝
  → 双方各自完成本次会话同意
  → 共同揭晓一件纪念物
  → 任一方可撤回共享
```

对方收到的不是监控邀请，而是：

> **「要不要一起做一个只属于我们的东西？」**

### 2.3 什么不是击穿体验

- 「打开 App 看仪表盘」
- 「生成一首歌」而无来源、时机、主权
- 「情侣心跳同步」而无双方目的、同意与退出
- 任何需要先读懂五个产品域才能感到价值的路径

Consent Center、Vault、Studio 是护栏与深化，不是首击穿。

## 3. 规模获取：礼物病毒，而非成瘾病毒

### 3.1 原则

宪章否决：无限流、连续签到、羞耻召回、关系分数、高频推送。  
因此规模路径只能是：

> **「我想把这个只对你有意义的东西送给你。」**

传播原子不是 App，不是内容流，而是：

**一件可感知、可带邀请入口、但不暴露原料的「仪式礼物」。**

### 3.2 病毒循环

```text
我完成一次有意义的仪式（MRCR+）
  → 想送给一个人（一对一，非广播）
    → TA 先体验成品，再选择「我也做一个」
      → TA 为自己完成 / 再回赠
        → 双方自愿再次共创
```

| 可做 | 不可做 |
|---|---|
| 站外可体验成品摘要 + 过期邀请链接 | 站外暴露原料、诊断、画像 |
| 一键生成可撤回的双人礼物邀请 | 「TA 已读 / 已拒」施压 |
| 用稀缺与 defer 作为品牌叙事 | 用推送量与 DAU 优化召回 |
| 非激励口碑与礼赠订阅 | 无限生成玩具化分享 |

增长北极星仍是 **MRCR（有意义仪式完成率）**；病毒是副作用，不是目标函数。

### 3.3 唯一优先增长实验

**单人仪式完成后 → 一键生成可撤回的双人礼物邀请。**

这是同时服务本质体验、又可能形成规模的最小杠杆。详见 [METRICS_GROWTH_AND_BUSINESS](./METRICS_GROWTH_AND_BUSINESS.md) 护栏约束下的 GTM。

## 4. 载体形态开放研讨

### 4.1 决策问题

载体回答的是：**用户第一次「感到 LifeWake」时，身体里装的是什么品类预期？**

错误载体会把「被看见的仪式」扭曲成「效率工具」或「消遣游戏」。

### 4.2 候选载体与张力

| 载体 | 用户默认预期 | 与 LifeWake 的契合 | 主要风险 |
|---|---|---|---|
| **功能性 App（工具）** | 解决任务、提高效率、可配置 | Consent / 撤回 / 导出等主权能力自然 | 易做成仪表盘、设置地狱；情感变功能列表 |
| **内容/社交 App** | 信息流、互动、关注 | 礼物分享有渠道 | 无限流与 DAU 引力直接违背慢灵感 |
| **游戏 / 玩法壳** | 沉浸、规则、目标、可重复乐趣 | 「仪式揭晓」「共走一刻」有 Journey/动森式共鸣 | 易被理解为消遣；成就/排行会腐蚀解释主权 |
| **互动艺术 / 展览体验** | 一次独特、被打动、可离开 | 最贴近「被看见的仪式」 | 难日用、难规模、难做持续同意治理 |
| **可穿戴伴侣 / 系统插件** | 常在、轻触达、身体信号近场 | pulse / 时机感知强 | 易滑向健康监测与焦虑通知 |
| **即时通讯内的小程序/Bot** | 低门槛、礼物可转 | 双人邀请路径最短 | 平台算法与留存压力；隐私边界弱 |
| **实体仪式物件 + 数字钥匙** | 信物感、稀缺 | 纪念物叙事强 | 供应链重；非 MVP |

### 4.3 三种可行路线（含取舍）

#### 路线 A：主权工具型 App（Functional-first）

- **形态**：标准移动 App；Home 极简；设置与同意完整。
- **优点**：治理、撤回、导出、审计最好做；企业/合规叙事清晰。
- **缺点**：首感偏「又一个 App」；击穿仪式感弱，需强设计补偿。
- **适合**：隐私敏感人群、内测治理验证、Studio 工具侧。

#### 路线 B：慢游戏 / 仪式玩法壳（Ritual-game hybrid）

- **形态**：像《风之旅人》/动森式「有规则的情感空间」，但无战斗、无排行、无强制每日任务。
- **优点**：天然承载揭晓、共在、稀缺；传播话术好懂（「我们做了一场双人仪式」）。
- **缺点**：商店分类与审核预期混乱；易被要求加「更多关卡」；技术上需实时会话与表现层，成本高。
- **适合**：Bond/Duet 作为主叙事的消费品牌。

#### 路线 C：推荐——「仪式壳层 + 主权内核」（Ritual Shell / Utility Core）

```text
外层（用户感知的品类）：仪式 / 礼物 / 互动艺术
内层（不可谈判的系统）：同意、撤回、时机、审计、导出
载体落点：轻量移动客户端（可先 Web/原型）
         + 可过期礼物链接（传播面）
         + 可选穿戴会话插件（pulse，非健康 App）
```

| 设计规则 | 含义 |
|---|---|
| 外层像艺术与礼物 | 首屏是「为此刻做一件事 / 送给 TA」，不是功能宫格 |
| 内层像银行级主权工具 | Consent / Revoke / Export 稳定、可寻、不可付费墙 |
| 玩法允许，游戏化指标禁止 | 可有揭晓动效、共创节奏；禁止 XP、连胜、亲密分 |
| 可离开即成功 | 完成仪式后安静；不追「明日再来」羞耻 |

**结论（v1 产品决策）：**

> LifeWake **不是**纯功能 App，也 **不是**传统游戏。  
> 它是 **以仪式/礼物为感知载体、以主权工具为系统内核** 的体验产品。  
> 商店与技术实现上可归类为消费级 App；体验语法上对齐互动艺术与慢游戏，对齐工具的是隐私与控制，而非效率。

### 4.4 分阶段载体策略

| 阶段 | 载体 | 目的 |
|---|---|---|
| Alpha | Web/原型 RitualView + 报告验收 | 验证「这就是我」与 defer/撤回 |
| Beta | 轻量移动客户端 + 过期礼物链接 | 验证双人邀请与礼物病毒 |
| Launch | App（仪式壳）+ 可选设备会话 + 礼赠订阅 | 规模与付费；仍禁止内容流壳 |
| 可选延伸 | 小程序仅作邀请落地；独立游戏化 SKU 需另立宪章评审 | 不默认主航道 |

## 5. 能力特性 → 必要技术能力

从本质体验反推「必须能做到」，而不是「平台有什么就用什么」。

| 产品能力特性 | 用户可感知结果 | 必要技术能力 |
|---|---|---|
| 最小授权创作 | 只用我选的材料 | 细粒度 consent、purpose 绑定、最小化数据采集 |
| 可解释仪式 | 知道为何是我/现在 | `inspiration_trace`、来源引用、用途收据 |
| 慢灵感 / 沉默 | 现在不打扰也成立 | `TimingDecision`、defer 队列、反刷屏频率护栏 |
| 情感炼金 | 抽象信号 → 可感知模态 | 多模态生成编排、质量门禁、失败降级 |
| 身体会话（pulse） | 听见此刻节律，非医疗 | 会话级设备连接、断连安全态、原始流短留存/销毁 |
| 双向共创 | 我们的作品，不是我发给你 | 多方独立授权、Bond 状态机、互惠校验 |
| 可撤回记忆 | 删得掉、撤得回 | 共享 ACL、即时失效、审计、导出/删除对等 |
| 反馈裁决现实 | 「不对」能推翻模型 | EmotionImpact、rubric、人工策展、禁止模型单裁决 |
| 礼物传播 | 站外可感、站内完整 | 可过期分享令牌、原料不出站、邀请→同意桥接 |
| 受控演化 | 产品变好但不偷改我 | ChangeSet 草案、人工/策略审批、`auto_apply: false` 默认 |

## 6. 必要技术标准（重新研讨）

下列标准是**产品成立的最低技术宪法**。可分期实现，不可在实验中绕过语义。

### 6.1 治理与主权标准（G）

| 标准 ID | 要求 | 验收要点 |
|---|---|---|
| TS-G1 同意完备 | 每次处理绑定主体、控制者、purpose、scope、期限、处理者 | 缺一不可采集/生成/通知/共享 |
| TS-G2 撤回即时性 | 个人撤回与共享撤回均有强制生效时限（目标 P95 可测） | 撤回后新处理事件数 = 0 |
| TS-G3 多方对等 | 共同作品不可单方永久控制 | duet 交付前双方 grant = 100% |
| TS-G4 用途锁定 | 仅 `create_for_user`（及明确列出的保管/导出）；禁止画像/广告/评分/诊断 | 策略引擎硬拒绝 |
| TS-G5 未成年人与危机 | 外发与高刺激路径受限；危机停止娱乐化生成 | 安全路径可测 |

契约锚点：`schemas/consent_record.schema.json`、`schemas/bond_cocreation.schema.json`。

### 6.2 仪式与交互标准（Π）

| 标准 ID | 要求 | 验收要点 |
|---|---|---|
| TS-P1 RitualEnvelope | 一切交付物进入统一信封：参与者、目的、模态、trace、同意引用、时机、动作、状态 | 无裸内容直出 |
| TS-P2 单焦点揭晓 | 客户端同时最多一个「现在可揭晓」 | 无无限流协议 |
| TS-P3 礼物令牌 | 外部分享为过期、可撤销、无原料的能力令牌 | 撤回后链接失效 |
| TS-P4 能力语义化 | Agent/UI 只调 `lw.*`，不直连厂商 SDK | connector 可替换 |

契约锚点：`schemas/ritual_envelope.schema.json`、[CAPABILITY_CONTRACTS](./CAPABILITY_CONTRACTS.md)。

### 6.3 时机与节奏标准（R / Policy）

| 标准 ID | 要求 | 验收要点 |
|---|---|---|
| TS-T1 TimingDecision | `DELIVER_NOW` / `SLOW_INSPIRATION_DEFERRED` / `CANCEL` 必有 reason_code | defer 不是错误伪装 |
| TS-T2 频率护栏 | 硬上限不可被实验关闭 | 打扰反馈率可观测 |
| TS-T3 安静优先 | defer 不制造红点焦虑、倒计时羞耻 | 文案与通知规范 |

### 6.4 情感与质量标准（E）

| 标准 ID | 要求 | 验收要点 |
|---|---|---|
| TS-E1 EmotionImpact | 用户反馈为主，rubric 为辅，模型分不得单独放行 | 低冲击拦截可解释 |
| TS-E2 意义确认 | MRCR 分母/分子定义固定；模型 wow 不可代填 meaningful | 指标防伪造 |
| TS-E3 ChangeSet | 反馈只产草案；默认不自动写回用户策略 | `auto_apply: false` |

契约锚点：`schemas/emotion_impact.schema.json`、[FEEDBACK_CHANGESET](./FEEDBACK_CHANGESET.md)。

### 6.5 数据与隐私工程标准

| 标准 ID | 要求 | 验收要点 |
|---|---|---|
| TS-D1 最小必要 | 会话原始 pulse/音频默认不入长期库 | 保留策略可测 |
| TS-D2 加密与隔离 | 个人空间与共同空间 ACL 分离；共同资产双控 | 越权用例失败 |
| TS-D3 遥测净化 | 埋点禁原料与自由文本正文、禁伴侣拒绝理由 | 采集表合规 |
| TS-D4 可迁移 | 导出格式开放；删除对等 | 无数据锁定商业 |

### 6.6 表现与客户端标准（载体相关）

| 标准 ID | 要求 | 验收要点 |
|---|---|---|
| TS-U1 仪式壳优先 | 首路径不经功能宫格 | 单点击穿可走通 |
| TS-U2 控制面稳定 | 同意/暂停/撤回/返回/字幕位置稳定 | 液态视觉可变、控制不可丢 |
| TS-U3 反游戏化指标 | 客户端不实现 XP/连胜/亲密分/排行 | 代码与设计评审红线 |
| TS-U4 离场友好 | 完成或 defer 后允许真正离开 | 无强制明日召回 |

### 6.7 明确非标准（禁止升格为「技术能力」）

- 人格/健康/关系质量推断 API
- 广告画像与跨 App 追踪
- 无限推荐流协议
- 自动代发消息到社交网络
- 以 DAU/时长为优化目标的推荐模型

## 7. 对应架构设计

### 7.1 架构原则

1. **体验叙事在上，平台能力在下**：用户只认识仪式与礼物；UAS 是承载，不抢叙事。
2. **主权内核横切所有层**：任何生成/分享管道必过 consent 与 revoke 平面。
3. **单一交付焦点**：编排目标是产出/延期一个 `RitualEnvelope`，不是堆并行功能。
4. **连接器可替换**：设备与多模态经 `lw.*`；mock → 真实不改产品语义。
5. **演化受控**：反馈进审计与 ChangeSet，不进静默模型微调用户。


### 7.3 与 UAS / SelfPaw 的边界

| 层次 | 职责 | 不职责 |
|---|---|---|
| UAS Kernel | 意图、运行时、治理原语、审计、演化管道、全局协议 | 不定义「生命仪式」审美与玩法 |
| SelfPaw Core | 个人身份、记忆、个人世界模型、通用执行 | 不写死 LifeWake 体验 |

| Ritual Shell 客户端 | 击穿体验、表现、本地安静偏好 | 不直连厂商、不做画像 |

详见 [LIFEWAKE_USER_AGI_EXPERIENCE_DOMAIN](../strategic/LIFEWAKE_USER_AGI_EXPERIENCE_DOMAIN.md)。

### 7.4 关键运行时路径

**单人击穿**

```text
UI: create_for_moment
 → lw.consent.check
 → signal.select (最小材料)
 → lw.surprise.compose | lw.pulse.compose
 → timing.decide
     ├─ DELIVER_NOW → RitualEnvelope → RitualView → EmotionImpact
     └─ DEFERRED → 安静队列（可取消）
 → optional: gift.token.mint（用户主动）
```

**双人击穿**

```text
UI: invite_duet
 → B: consent.independent
 → A+B: session consents
 → lw.pulse.duet | bond.cocreate
 → Bond Guardian（对称需求）
 → RitualEnvelope (shared)
 → ShareGrant
 → either party: share.revoke → SHARE_REVOKED 全入口失效
```

### 7.5 部署形态（与载体一致）

| 阶段 | 部署 | 说明 |
|---|---|---|
| v0.1 现态 | 单一 `projects/lifewake` subapp + mock connectors | 验证语义与 CASE，不拆微服务 |
| Beta | Shell 客户端 + Domain API（仍可单体）+ Gift Edge 轻服务 | 礼物令牌与撤回失效要独立可测 |
| Launch | 主权/编排核心可仍内聚；生成与媒体存储按成本外置 | **禁止**为「社交化」拆出推荐微服务 |

原则：**先保证信封与同意平面正确，再水平扩展生成算力**；不为 DAU 架构。

### 7.6 安全与失败架构

```text
Safety > Consent > Relationship readiness > Quiet prefs > Quality > Confidence > Delivery
```

| 失败 | 系统行为 |
|---|---|
| 同意缺失/撤回 | 停止管道；清理待推送 |
| 质量低 / 低冲击 | 草稿、重炼或人工策展；不伪装成功 |
| 时机不合 | `SLOW_INSPIRATION_DEFERRED` |
| 设备断连 | 重连 / 降级 / 结束；保持治理状态 |
| 共享撤回 | 全入口即时 `SHARE_REVOKED` |
| 危机/未成年外发 | 停止娱乐化；安全路径 |

## 8. 决策摘要（可引用）

| 议题 | 决策 |
|---|---|
| 本质价值 | 被看见的私人仪式；成功可等于完成后离开 |
| 单点击穿 | 丢材料 → 揭晓「这是我」；双人各点一次同意 → 共同纪念物 |
| 规模 | 礼物病毒（一对一深传）；北极星 MRCR |
| 载体 | **仪式壳层 + 主权内核**；非纯工具 App，非传统游戏 |
| 技术宪法 | 同意/撤回/信封/时机/情感裁决/无原料外发 为硬标准 |
| 架构 | Shell · Sovereignty · Orchestrator · lw.* · Connectors，卧于 SelfPaw Domain Pack |

## 9. 守恒检查（本文新增项）

每个涉及载体、增长或架构的 ChangeSet / PRD 额外回答：

1. 是否仍能用一句话说清「被看见的仪式」？

3. 若引入玩法，是否引入了 XP/排行/催促？

5. 新服务拆分是否为生成成本/可靠性，而非为推荐与留存？
